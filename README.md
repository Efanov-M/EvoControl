# EvoControl

**EvoControl** — веб-приложение для учёта эвакуированных транспортных средств, управления автопарком эвакуаторов, водителями, стоянками и операциями эвакуации.

Проект разрабатывается на Python с использованием Django и представляет собой практическую систему автоматизации процессов эвакуационной службы.

**Статус:** в активной разработке (учебный и портфолио-проект).

## О проекте

Цель EvoControl — объединить информацию о транспортных средствах, эвакуаторах, водителях, стоянках и операциях в единой информационной системе.

Приложение ориентировано на задачи диспетчерского и оперативного учёта.

В перспективе система должна позволять отслеживать полный жизненный цикл эвакуированного автомобиля: от регистрации эвакуации и размещения на стоянке до перемещения, выдачи владельцу и сохранения истории действий.

Проект также используется для практического освоения backend-разработки, проектирования реляционных баз данных и архитектуры Django-приложений.

## Архитектура проекта

EvoControl построен на архитектуре Django MVT (Model–View–Template).

- **Model** — описание данных, связей между сущностями и ограничений.
- **View** — обработка HTTP-запросов, взаимодействие с моделями и подготовка данных.
- **Template** — формирование HTML-страниц с использованием Django Template Language.

Для разделения ответственности система организована в виде нескольких Django-приложений.

### Основные функциональные области

| Компонент | Назначение |
|---|---|
| Vehicles | Учёт эвакуированных автомобилей |
| Fleet | Учёт эвакуаторов и автопарка |
| Drivers | Информация о водителях |
| Parking | Учёт стоянок |
| Operations | Регистрация и история операций |
| Accounts | Пользователи и управление доступом |

Каждая область отвечает за отдельную часть предметной модели.

## Функциональные возможности

### Учёт автомобилей

Разрабатывается функциональность управления информацией об эвакуированных транспортных средствах.

Основные задачи:

- Регистрация автомобилей.
- Просмотр списка автомобилей.
- Просмотр детальной информации.
- Редактирование данных.
- Удаление записей.
- Связь автомобилей с операциями эвакуации.

Для работы с данными используются Django Models, ModelForm, Views и ORM.

### Управление автопарком

Приложение Fleet предназначено для ведения реестра эвакуаторов.

В карточке эвакуатора предусмотрены:

- Марка и модель.
- Государственный регистрационный номер.
- Тип эвакуатора.
- VIN.
- Статус активности.
- Раздел истории связанных операций.

Информация об эвакуаторах отображается через Django Templates.

### Учёт водителей

Отдельная функциональная область предназначена для хранения и управления сведениями о водителях эвакуационной службы.

В дальнейшем данные водителей будут использоваться при регистрации и анализе выполненных операций.

### Учёт стоянок

Система предусматривает отдельный учёт стоянок, связанных с размещением эвакуированных автомобилей.

Планируется развитие функциональности контроля размещения и перемещения автомобилей между стоянками.

### Операции эвакуации

Для операций предусмотрена модель `VehicleOperation`.

Она служит основой для учёта событий, связанных с транспортными средствами, эвакуаторами, сотрудниками и стоянками.

Полноценная бизнес-логика операций находится в разработке.

Планируемый жизненный цикл транспортного средства:

```text
Регистрация
     |
     v
Эвакуация
     |
     v
Приём на стоянку
     |
     v
Хранение
     |
     +----> Перемещение
     |           |
     |<----------+
     |
     v
Выдача
     |
     v
История операций
```

Одна из основных архитектурных задач — обеспечить согласованность данных при выполнении операций и исключить недопустимые изменения состояния автомобиля.

### Пользователи

Для системы предусмотрено отдельное приложение Accounts с использованием механизмов пользователей Django.

Дальнейшее развитие включает:

Используемые и изучаемые механизмы:

- Обратные связи между моделями.
- QuerySet.
- Миграции схемы базы данных.
- ModelForm.

По мере развития проекта планируется внедрение дополнительных ограничений целостности данных, транзакций и оптимизации ORM-запросов.

## Локальный запуск

Для локальной разработки необходим Python, совместимый с используемой версией Django.

### 1. Получение исходного кода

Клонируйте репозиторий EvoControl и перейдите в каталог проекта.

### 2. Создание виртуального окружения

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Для Windows:

```powershell
.venv\Scripts\activate
```

### 3. Установка зависимостей

Если репозиторий содержит `requirements.txt`:

```bash
python -m pip install -r requirements.txt
```

### 4. Подготовка базы данных

Из каталога, содержащего `manage.py`, выполните:

```bash
python manage.py migrate
```

### 5. Создание администратора

При необходимости:

```bash
python manage.py createsuperuser
```

### 6. Запуск сервера

```bash
python manage.py runserver
```

После запуска приложение по умолчанию доступно по адресу:

http://127.0.0.1:8000/

> Инструкции приведены для стандартного локального Django-окружения. Дополнительные настройки и зависимости необходимо сверить с конфигурацией конкретной версии проекта.
